# Watermarking

`phlox` supports two independent watermarks on every output:

| Kind | Set by | Typical use |
|------|--------|-------------|
| **User watermark** | Caller, per render, via `RenderContext.setUserWatermark(...)` | "DRAFT", "PRELIMINARY", "COPY", customer-defined labels. Optional — default is none. |
| **Program watermark** | Distribution (open-source vs commercial), once at startup, via `PhloxProgramWatermark.setInstance(...)` | A small attribution marker that identifies the library and edition. Defaults to an "open source" marker; the commercial distribution replaces or removes it. |

Both watermarks are supported in both HTML and PDF output. They render independently: a PDF can carry a customer-defined "DRAFT" watermark **and** the small library attribution at the same time, without one interfering with the other.

## `WatermarkSpec` (phlox-api)

The shared shape used by both watermark kinds:

```java
package com.helger.phlox.api.watermark;

public final class WatermarkSpec
{
  private final String m_sText;
  private float        m_fOpacity   = 0.10f;          // 0..1
  private float        m_fRotation  = -45f;           // degrees, anchored at center
  private Color        m_aColor     = Color.GRAY;
  private EWatermarkPosition m_ePosition = CENTER;    // CENTER | TOP | BOTTOM | FOOTER_RIGHT
  private float        m_fFontSizePt = 72f;           // PDF: point size; HTML: em-equivalent
  private boolean      m_bRepeatPerPage = true;       // PDF: every page; HTML: every printed page

  public static WatermarkSpec text (@Nonnull String sText) { ... }
  // chainable setters omitted
}
```

The same `WatermarkSpec` is consumed by both writers; each one interprets it for its medium. Spec lives in `phlox-api`, so no writer-library types leak through.

## User watermark — `RenderContext.setUserWatermark(...)`

```java
final PdfRenderContext aCtx = new PdfRenderContext ()
    .setLocale (Locale.GERMAN)
    .setUserWatermark (WatermarkSpec.text ("ENTWURF")
        .setOpacity (0.12f)
        .setRotation (-30f));

new PdfInvoiceWriter ().writeTo (aInvoice, aCtx, aOutputStream);
```

Defaults to `null` (no user watermark). Lives on the base `RenderContext` because every writer supports it identically.

## Program watermark — `PhloxProgramWatermark`

A library-wide attribution marker, set once at JVM startup. Independent of any per-render configuration.

```java
package com.helger.phlox.api.watermark;

public final class PhloxProgramWatermark
{
  // Default for the open-source distribution
  private static final WatermarkSpec OPEN_SOURCE_DEFAULT = WatermarkSpec
      .text ("Generated by phlox · open-source edition · github.com/phax/phlox")
      .setOpacity (0.35f)
      .setRotation (0f)
      .setPosition (EWatermarkPosition.FOOTER_RIGHT)
      .setFontSizePt (6f)
      .setRepeatPerPage (true);

  private static volatile WatermarkSpec s_aActive = OPEN_SOURCE_DEFAULT;

  /** Replaces (or with null, suppresses) the program watermark. */
  public static void setInstance (@Nullable WatermarkSpec aSpec) { s_aActive = aSpec; }

  @Nullable
  public static WatermarkSpec getInstance () { return s_aActive; }
}
```

**Default behaviour (open-source build):** a small, low-opacity attribution line in the bottom-right corner of every page. Just visible enough that an observer can tell the document was rendered with `phlox`, but not large enough to clutter the layout.

**Commercial distribution:** the commercial JAR calls `PhloxProgramWatermark.setInstance(null)` in a static initializer (typically gated on a license check) and the attribution disappears. The same hook can also replace the spec with a different marker — e.g. a customer's vendor brand.

**Apache 2.0 reminder.** The library is Apache-licensed; nothing stops a user from calling `setInstance(null)` themselves. This is by design — the watermark is a deliberate, easily-overridden signal, not a DRM mechanism. Its purpose is to make the default "look" of an open-source render distinct from a commercial one without forcing a build flag.

## How writers realize a watermark

### `HtmlInvoiceWriter`

For each non-null watermark, the writer emits one `<div>` inside `<body>` with class `phlox-watermark-user` / `phlox-watermark-program` and an inline style block in `<head>`. The CSS uses `position: fixed` for on-screen viewing and a `@media print` block so the watermark also lands on printed pages:

```html
<style>
  .phlox-watermark-user {
    position: fixed; top: 50%; left: 50%;
    transform: translate(-50%, -50%) rotate(-30deg);
    font-size: 6em; color: rgba(128,128,128,0.12);
    pointer-events: none; z-index: 9999;
    user-select: none;
  }
  @media print {
    .phlox-watermark-user { position: fixed; }   /* repeats on each printed page */
  }
  .phlox-watermark-program {
    position: fixed; bottom: 4mm; right: 4mm;
    font-size: 0.5em; color: rgba(128,128,128,0.35);
    pointer-events: none; z-index: 9999;
  }
</style>
<body>
  <div class="phlox-watermark-user" aria-hidden="true">ENTWURF</div>
  <div class="phlox-watermark-program" aria-hidden="true">Generated by phlox · …</div>
  …
</body>
```

No JavaScript is required. The print-media behaviour for repeating watermarks across page breaks is browser-implemented and works in all modern engines (Chromium, Firefox, WebKit). If the rendered HTML is later converted to PDF by a headless browser, the watermark survives that path too.

`aria-hidden="true"` keeps the watermark out of accessibility trees and out of "select all" copy-paste, matching how user-agent print stylesheets handle decorative overlays.

### `PdfInvoiceWriter`

`ph-pdf-layout` does not have a first-class "watermark" element, so the writer overlays one via a custom page decorator: for each rendered page, the decorator draws a rotated `PLText` (user watermark, large, centered, low-opacity) and/or a small footer-anchored `PLText` (program watermark). Color, opacity, rotation, and font size all come from the `WatermarkSpec`. The watermark is rendered on top of the page content — not behind it — so it remains legible regardless of background tint.

When both watermarks are present, the user watermark draws first (background-most) and the program watermark draws last (top-most, in the corner). They never overlap because their `EWatermarkPosition`s are different by construction.

## CLI exposure (`phlox-cli`)

The CLI exposes user watermark options only — program watermarking is a build-time concern, not a per-invocation one.

```
phlox render --in invoice.xml --out invoice.pdf --format pdf \
             --watermark "DRAFT" --watermark-opacity 0.15 --watermark-rotation -45
```

## What watermarking does **not** do

- It does not redact, encrypt, or otherwise restrict access to the underlying invoice data — the source XML and the document content are unchanged.
- It does not satisfy any regulatory "watermarking" requirements (e.g. anti-fraud document marking). Treat it as visual annotation only.
- It does not enforce licensing — the program watermark is overrideable. Anything stronger belongs in the commercial distribution's licensing layer, not in `phlox-api`.
